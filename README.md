# Bot Manager — PWA для керування Telegram-ботами

Клієнтський (client-side only) веб-застосунок у стилі Telegram, що працює напряму з
`https://api.telegram.org` без будь-якого проміжного сервера. Встановлюється як PWA
на телефон/ПК прямо з браузера.

## 🚀 Розгортання на GitHub Pages (2 хвилини)

1. Створіть новий публічний репозиторій на GitHub (наприклад `bot-manager`).
2. Завантажте всі файли цього проєкту в корінь репозиторію (можна перетягнути в
   веб-інтерфейс GitHub: "Add file → Upload files", або через git:
   ```bash
   git init
   git add .
   git commit -m "Bot Manager PWA"
   git branch -M main
   git remote add origin https://github.com/<ваш-логін>/bot-manager.git
   git push -u origin main
   ```
3. У репозиторії відкрийте **Settings → Pages**.
4. У розділі "Build and deployment" оберіть **Source: Deploy from a branch**,
   гілку **main**, папку **/ (root)** → **Save**.
5. За 1–2 хвилини застосунок буде доступний за адресою:
   `https://<ваш-логін>.github.io/bot-manager/`
6. Відкрийте посилання в Chrome/Edge/Safari → з'явиться пропозиція "Встановити застосунок"
   (або "Додати на головний екран" на мобільному) — це і є встановлення PWA.

Репозиторій може лишатися **публічним**: у коді немає жодних секретів — токени
ботів користувачі вводять самі, і вони зберігаються тільки в їхньому браузері.

## 🔒 Безпека та архітектура

- **Без бекенду.** Увесь код виконується в браузері користувача. Запити йдуть
  лише на `api.telegram.org` (виклики методів) та `api.telegram.org/file/...`
  (завантаження медіа).
- **Локальне зберігання.** Токени ботів, список чатів і повідомлення зберігаються
  в **IndexedDB** браузера.
- **Шифрування PIN-кодом.** За бажанням користувач встановлює 4-значний PIN.
  Ключ AES-256-GCM виводиться з PIN через **PBKDF2 (210 000 ітерацій, SHA-256)**
  у Web Crypto API й існує лише в оперативній пам'яті поточної сесії — на диск
  ключ ніколи не пишеться. Боти, чати й повідомлення шифруються перед записом
  у IndexedDB.
- **Немає "магічного" відновлення пароля.** Забутий PIN означає, що зашифровані
  дані відновити неможливо (за задумом) — лишається імпортувати бекап або
  додати ботів заново (токени можна перевипустити через @BotFather).

## ⚠️ Про Webhook

Bot API підтримує два способи отримання оновлень: **Long Polling** та **Webhook**.
GitHub Pages — це **статичний хостинг**, який фізично не може приймати вхідні
POST-запити від Telegram (немає сервера, що слухає порт). Тому:
- **Long Polling працює повністю** й це основний режим застосунку — під час
  роботи вкладки браузер сам регулярно опитує Telegram.
- **Webhook** у застосунку можна лише *зареєструвати на боці Telegram* (вказавши
  URL стороннього сервера — наприклад, власного Cloudflare Worker), але сам
  застосунок на GitHub Pages приймати ці запити не буде. Це фундаментальне
  обмеження статичного хостингу, а не недолік коду.

## 🧩 Що реалізовано

- Мультиакаунтинг ботів (додавання за токеном через перевірку `getMe`, перемикання, видалення з ізоляцією даних).
- Long Polling із збереженням `offset` в IndexedDB (без втрати повідомлень при перезапуску).
- Три-панельний інтерфейс у стилі Telegram: список ботів/чатів, вікно чату, картка користувача з повним JSON від Bot API.
- Теми: світла / темна / системна, 6 акцентних кольорів.
- Надсилання тексту (Enter — відправити, Shift+Enter — новий рядок), форматування вхідних повідомлень (bold/italic/code/pre/strikethrough/underline/spoiler/blockquote/посилання).
- Надсилання фото/відео/голосових/документів через прикріплення файлу.
- Відображення фото, відео, відеоповідомлень (кружечки), голосових (з візуалізацією хвиль), стікерів (WEBP і WEBM — повністю; анімовані TGS — через lottie-web/pako з CDN), опитувань, геопозиції, контактів, inline-клавіатур, reply-цитат.
- `sendChatAction`, `answerCallbackQuery`, `forwardMessage`, `deleteMessage`, реакції (`setMessageReaction`) — доступні через API-обгортку `js/api.js`.
- Редагування профілю бота (ім'я, опис, коротке опис, команди меню) напряму з інтерфейсу.
- Експорт/імпорт зашифрованого бекапу бази даних у JSON.
- Кешування медіа через IndexedDB + Service Worker, автоматичне обрізання (pruning) старих медіа та повідомлень понад ліміт (`js/db.js → pruneMessages/pruneMediaCache`).
- Проста віртуалізація списку повідомлень (підвантаження вікном по 40 повідомлень, кнопка "Завантажити попередні").
- Повноцінний PWA: `manifest.json`, `sw.js`, іконки, встановлення на пристрій, офлайн-кеш app shell.

## 📝 Чесно про обмеження цієї версії

Це велика робоча основа, а не буквально кожен байт Bot API — нижче те, що варто
знати перед продакшн-використанням:

- **Аватар бота** Telegram Bot API дозволяє встановити лише вручну через
  @BotFather — офіційного методу API для цього не існує (у застосунку це
  явно вказано в налаштуваннях).
- Кнопки **inline-клавіатур із `callback_data`** показуються, але клацнути їх
  "від імені користувача" з адміністраторського застосунку не можна — це
  завжди робить клієнт Telegram; кнопки з `url` відкриваються нормально.
  Оновлення через реальний `callback_query` від користувачів застосунок
  обробляє (автоматично шле `answerCallbackQuery`).
- **Push-сповіщення** через Service Worker увімкнено на рівні UI/дозволів;
  для реальної доставки push, коли вкладка закрита, знадобиться Push-сервер
  (Web Push вимагає бекенд для відправки — так само фундаментальне
  обмеження чистого client-side/GitHub Pages, як і з Webhook).
- **Reply-клавіатури** (клавіатура, що замінює системну) відображаються лише
  як частина даних повідомлення (JSON-панель), окремого рендеру немає —
  легко додати за потреби.
- Побудова inline/reply-клавіатур для власних повідомлень наразі не має
  окремого UI-конструктора — додайте `reply_markup` у `js/app.js →
  sendCurrentMessage()` за потреби.

Код організовано модульно (`js/crypto.js`, `js/db.js`, `js/api.js`, `js/app.js`),
тому розширення будь-якого з цих пунктів — питання десятків рядків, а не
переписування архітектури.

## 📁 Структура проєкту

```
index.html          — розмітка інтерфейсу
manifest.json        — Web App Manifest
sw.js                 — Service Worker (кеш app shell + медіа, push)
css/style.css         — стилі у стилі Telegram (світла/темна/системна теми)
js/crypto.js          — AES-GCM шифрування, PBKDF2 з PIN
js/db.js               — обгортка IndexedDB з прозорим шифруванням і pruning
js/api.js              — обгортка Telegram Bot API + Long Polling manager
js/app.js              — стан застосунку, рендеринг UI, обробка подій
icons/                 — іконки PWA (192/512, звичайні та maskable)
```

## 🛠 Локальний запуск для розробки

Service Worker вимагає HTTPS або `localhost`, тому просто відкрити `index.html`
подвійним кліком не вийде — потрібен локальний сервер:

```bash
python3 -m http.server 8080
# або
npx serve .
```

Відкрийте `http://localhost:8080`.
